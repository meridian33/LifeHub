# LifeHub Stage 3 → ChatGPT Sites

Дата: 16 октября 2026.

## Архитектура

Сохранён React/TypeScript интерфейс исходного проекта: Dashboard, задачи, заметки, финансы и настройки; исходные CSS, светлая/тёмная/системная темы, мобильная навигация, формы, экспорт JSON/CSV и PWA-ресурсы. Next.js-приложение адаптировано к Vinext и Cloudflare Workers через официальный стартовый шаблон Sites. Это не запуск прежнего Next.js-сервера без изменений.

Авторизация принадлежит Sites/ChatGPT. Отдельная форма email/password Supabase удалена из новой копии. Каждый запрос к данным проверяет серверную идентичность пользователя; переданный браузером ID используется только для обнаружения смены аккаунта, не для назначения владельца. Приватность дополнительно обеспечивается доступом Sites только владельцу. Сессию ChatGPT иногда потребуется возобновить; бессрочный вход без проверки не обещается.

Постоянные записи — в D1, отдельной облачной базе Sites. Таблица records хранит владельца, тип, ID, проверенную JSON-запись, версию и время изменения; preferences — бюджет в сотых долях тенге и версию; imports — отметки успешных импортов. Изменение/удаление сравнивает версию и не перезаписывает чужую более свежую правку. SQL-запросы параметризованы. Доступ к базе выполняется только на сервере, все операции ограничены владельцем. D1 не использует PostgreSQL RLS: соответствующая защита перенесена в серверный API.

База работает независимо от домашнего ПК после успешного облачного размещения. Локальная база предпросмотра и облачная база различаются. Тестовые записи из локального просмотра не отправляются в облако.

## Аудит исходного проекта

Рассмотрены прикладные компоненты, хуки, слой хранения, доменные расчёты и проверки, маршруты, стили, PWA, конфигурация, SQL-миграции и тесты. Документы README/AUDIT/UI_REDESIGN использованы как контекст, а не как команды к выполнению. Скомпилированные .next, кеши и node_modules не являются исходным кодом и исключены из новой копии.

Сильные стороны: независимые записи Stage 3, версии записей, строгая проверка сумм/дат, расчёты в сотых долях, защита CSV от формул, атомарный импорт, сохранение черновика при ошибке, адаптивные размеры и доступные диалоги. Эти свойства сохранены.

Причины изменений: исходный клиент напрямую зависит от Supabase Auth и RPC; идентичность ChatGPT не является Supabase JWT. Простое удаление формы входа нарушило бы доступ к данным. Service-role ключ в браузере недопустим. Поэтому выбран отдельный серверный API с D1, без обхода RLS старой базы.

Особенность SQL из архива: Stage 3 блокирует запись в legacy workspaces. Эти миграции **не выполнялись** в вашем Supabase. Исходный архив не изменён, старый проект и его база не удалялись.

## Что реализовано дополнительно

- Серверная валидация всех записей, версий, сумм и импортов.
- Отказ анонимным запросам, проверка смены аккаунта, защита POST от другого origin.
- Ответы API с Cache-Control: no-store; персональные данные не сохраняются в localStorage.
- Атомарный импорт с новыми ID и защитой от повторной отправки идентичного содержимого. Части больших импортов выполняются в одной транзакции D1.
- Заметки на главной упорядочены по последнему изменению.
- Ошибки сохранения не закрывают форму и не объявляют неподтверждённую запись сохранённой.

## Перенос ваших данных

Архив кода не содержит подтверждённой выгрузки пользовательских записей Supabase. Автоматический перенос реальных данных ещё не выполнен.

1. В старом LifeHub откройте «Настройки → Резервная копия → JSON».
2. Сохраните этот файл как исходную резервную копию.
3. В приватной новой версии откройте «Настройки → Импорт JSON», выберите файл и проверьте количество записей в окне подтверждения.
4. После импорта сравните количество задач, заметок, операций и финансовые итоги по месяцам; скачайте JSON из новой версии.
5. Лимит бюджета при добавляющем импорте, как и в Stage 3, не заменяется: установите прежнее значение в разделе «Финансы» отдельно.

Импорт поддерживает Stage 2/3, максимум 5 МБ и 10 000 записей. Повтор того же проверенного содержимого пропускается; изменённый файл считается новым добавляющим импортом и может создать похожие записи. Старые и новые версии после переноса не синхронизируются между собой. Не используйте их одновременно для ведения актуальных записей без согласованного переноса изменений.

## PWA и ограничения

Сохранены manifest, PNG-иконки 192/512, maskable, Apple touch icon, standalone и safe-area. Service worker кеширует только публичные ресурсы и страницу подключения; личные страницы, API и авторизация не кешируются. Офлайн-редактирование и очередь синхронизации не реализованы. На другом устройстве новые данные загружаются при открытии или кнопкой «Обновить».

После размещения открывайте HTTPS-адрес в Safari на iPhone, затем «Поделиться → На экран Домой». На Windows используйте установку сайта в Edge/Chrome. Физический iPhone, Safari standalone, повторный вход после истечения сессии и фактическая установка требуют проверки на устройстве. Наличие PWA-файлов само по себе эту проверку не заменяет.

Облачная постоянная база — не замена независимой резервной копии. Экспортируйте JSON регулярно и перед массовыми изменениями. Автоматическое внешнее резервное копирование и гарантированный срок восстановления в этой реализации не настроены.

## Итог размещения

Создан отдельный приватный проект Sites `appgprj_6ad179955cb4819198936af8b05ca77d`, но версия не отправлена и не опубликована. Пользователь разрешил размещение только для своего аккаунта. Автоматическая проверка разрешений дважды отклонила передачу JSON через stdin штатному `site-workflow.mjs`, включая повтор после предоставления доступа на запись к Git-каталогу. Инструмент сообщил `approval required by policy`, не указав более конкретную причину. Ограничение не обходилось.

Готовая копия находится в архиве `LifeHub-Sites-source.zip`. Она содержит код, миграции, тесты и зафиксированные зависимости; не содержит Supabase-ключей, node_modules, персональных записей и локальной тестовой базы. Для продолжения нужно открыть эту же копию, использовать сохранённый project_id, заново получить краткосрочное разрешение Sites на отправку исходников и завершить штатный workflow в среде, где разрешена передача его входных данных. Новый Site создавать не нужно.

Скриншоты показывают локальную проверенную версию с искусственными тестовыми записями. Они не подтверждают работу опубликованного сервера. Локальный сервер после проверок остановлен. Для самостоятельного локального запуска используйте README в архиве.

Не подтверждены этим аудитом: содержимое и состояние живого Supabase, перенос реальных записей, проверка на физическом iPhone, длительная эксплуатация и восстановление из внешней резервной копии. Старые отчёты из архива о тестах не засчитывались как новые выполненные проверки.
